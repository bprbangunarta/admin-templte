Building a clean admin dashboard with design tokens

ZR Zulfadli RizalSep 10, 20265 min read

A design system doesn't have to be complicated. With a handful of CSS custom properties you can keep an entire admin dashboard consistent — spacing, color, typography and radius all flowing from one source of truth. In this guide we'll walk through the approach used across Mutiara.

Start with tokens, not components

Before styling a single button, define the vocabulary your interface speaks. Tokens are named values — --bg-card, --text-muted, --accent — that every component references instead of hard-coding a hex value. Change the token and the whole product updates.

Hard-coded colors are technical debt. A token is a promise that the value can change in exactly one place.

Make dark mode a first-class citizen

Because components never reference raw colors, supporting dark mode is simply redefining the tokens under a theme selector. No component code changes — the same markup renders correctly in both themes, including charts and maps.

  • Define the full light palette on :root.
  • Override only the tokens that change under the dark selector.
  • Let color-mix() derive soft backgrounds so they adapt automatically.

Keep spacing on a rhythm

Compact interfaces live or die by consistent spacing. Pick a small base unit and let padding, gaps and row heights snap to it. The result feels intentional rather than arbitrary, and dense screens stay readable.

Putting it together

Once tokens are in place, building new screens becomes assembly rather than authoring. Reach for existing components, lean on the spacing scale, and trust the palette. That's how a full dashboard — 46 pages and counting — stays coherent as it grows.
